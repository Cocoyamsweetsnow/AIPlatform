# 0003 用户鉴权：JWT + API Key + Argon2id

- 状态：**已落地（M2）**
- 日期：2026-11-08
- 决策者：项目负责人（AI 按 D8 推荐项执行）
- 影响范围：`src/auth/`、`src/http/server_{drogon,httplib}.cpp`、`src/main.cpp`、`src/config.*`、`CMakeLists.txt`、`Dockerfile`、`docker-compose.yml`

## 背景

M1 只有全局静态 `AIP_TOKEN`：所有持 Token 的人共享同一身份，会话没有归属，
无法做多租户、配额和审计。P0 的第二项是用户身份与会话隔离。

## 考虑过的方案

| 方案 | 优点 | 代价 | 结论 |
|---|---|---|---|
| **自建 JWT(HS256) + Argon2id + API Key** | 无外部依赖；与 roadmap 的 D8-A 一致；15 分钟 access + 7 天 refresh 够用 | 刷新令牌无状态、不能单条吊销；密钥轮转要自己实现 | **选择** |
| Keycloak / OIDC | 企业 SSO、MFA、令牌吊销 | 多一个要运维的服务；M2 阶段过重 | 留给企业客户 |
| 继续静态 Token | 最简单 | 无用户、无归属、无法计费/限流 | 仅保留为管理员 Token |

## 决定

1. **密码**：Argon2id（t=2, m=19 MiB, p=1, hash=32B, salt=16B），只存编码后的哈希。
   头文件随仓库分发（`third_party/argon2/include`），运行时依赖 `libargon2.so.1`。
2. **JWT**：HS256，claims 为 `iss/sub/email/role/type/iat/exp`。
   - access token 默认 15 分钟；refresh token 默认 7 天；
   - 刷新是无状态的：`POST /v1/auth/refresh` 只校验 refresh token 并重新签发，
     **没有服务端 refresh 记录，因此不能单条吊销**；禁用用户通过每次请求查库生效；
   - 多副本必须共享同一个 `AIP_JWT_SECRET`；未设置时启动生成临时 secret 并告警。
3. **API Key**：`aip_` + 32 字节随机十六进制；数据库只存 SHA-256 哈希与前缀，
   明文只在创建响应里返回一次；校验时更新 `last_used_at`，支持撤销。
4. **静态 `AIP_TOKEN`**：保留为管理员 Token（`is_admin=true, user_id=0`），
   可以访问所有会话；不能创建用户 API Key（需要 user_id）。
5. **鉴权入口**：
   - 公开：`/healthz`、`/v1/config`、内置静态资源、`/v1/auth/register|login|refresh`；
   - 受保护：对话、历史、`/v1/auth/me`、`/v1/auth/api-keys*`；
   - `AIP_AUTH_REQUIRED=1`、`AIP_TOKEN`、`AIP_JWT_SECRET` 任一存在即启用鉴权；
     三者都没有时保持本地开发模式（匿名管理员），仅用于内网/演示。
6. **会话归属**：`sessions.user_id` 在创建时写入当前用户；`owns()` 校验，
   普通用户跨用户访问返回 404（避免枚举），admin 可访问全部。
7. **HTTP 层**：
   - Drogon 在 `pre_routing` 里把 JWT/API Key 校验放到 `db_workers`（不阻塞 IO），
     校验结果放进 `req->attributes()["principal"]`；
   - httplib 回退在连接线程里同步校验（该后端本来就是每连接一线程）。
8. **不引入**：OIDC、短信/邮箱验证、找回密码、刷新令牌吊销列表、MFA；
   这些留给后续阶段。

## 后果

**正面**

- 会话按用户隔离；API Key 可独立撤销；静态管理员 Token 仍可用于运维；
- 密码哈希用 Argon2id，数据库泄露时离线破解成本高；
- 不引入外部身份服务，单机/私有化部署仍然只有一个二进制 + PostgreSQL；
- JWT access token 很短，即使泄露窗口也有限。

**负面 / 注意**

- JWT 是无状态的，修改密码/禁用用户后 token 在过期前理论上仍有效；
  禁用用户已在每次请求查库时拦截，但“改密码踢下线”还没做；
- refresh token 不能单条吊销；需要更强能力时上 Redis 黑名单或 OIDC；
- `AIP_JWT_SECRET` 轮转会让所有旧 token 失效，需要安排维护窗口；
- 注册接口没有邮箱验证/验证码，公开部署必须加限流（M3）和风控；
- 登录失败没有恒定时间假哈希；用户不存在时比密码错误略快，后续可补；
- API Key 的 `last_used_at` 在每次请求都写库，高频场景应改成异步/采样。
